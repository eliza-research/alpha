# Cloud QA launcher refinement

The exact Alpha staging QA launcher and pinned private-runtime helpers run in a disposable product directory with a synthetic Git source. The fixture supplies a closed child object and private input file. Its spawn hook verifies the selected entry, reviewed staging route, loopback bind, local owner authentication and stripped unrelated input settings. No runtime entry executes.

The replay observes actual profile marker, token and configuration custody. It covers fresh, reused and refused profiles, explicit and default source selection, protected ports, source entry absence and mismatched saved routing. The same child port drives normal exit, no-PID failure, signals, late revision failure, held receipt rename and failed receipt publication. The actual shared supervisor handles listeners, stops and close. The actual private writer creates, renames or cleans its temporary file. A receipt describes an attempt and can remain after the child has closed. In the held-rename case the child closes first and the receipt still publishes before the launcher reports cancellation.

The as-built linked-log scenario opens a preexisting symbolic link in a legitimate synthetic QA profile and changes the distinct target file from mode 0644 to 0600 before a no-PID spawn failure. Its bytes and link remain. The model records the observed mode change independently of the child and receipt safety properties.

The finite scope is one invocation, one selected child and one previous profile and receipt. Real port availability, concurrent invocations, independent path replacement, kernel signals, forced-kill timeout, real credentials, Cloud responses and Android acceptance remain separate.
