# Verified Calendar access choice

`GoogleCalendarAccessChoice` follows the mounted Allow Calendar changes
prompt. Its identity includes the exact verified account read and Calendar
intent. A fresh account list or intent withdraws the old choice. The
explicit Allow tap checks those identities again when its device receipt
arrives and before saving access.

The source campaign compares 118 checkpoints across 17 schedules in the
actual React panel. It holds Ask and Allow receipts while the same owner
rechecks accounts, another owner replaces them, or the Calendar intent
retires. A fresh read-only choice can continue to Google consent. A
fresh write-grant choice passes only its current verified rows to the
Calendar link helper. The driver's controlled ports capture exact access
save and consent effects.

Two Cloud bindings, four intents, six account reads and six held permission
captures bound this projection. Native persistence, provider effects and
the authorization return have separate scopes.
