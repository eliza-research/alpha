# Historical PhotosLibrary source replay

The campaign mounts flag-off Photos in Chromium and imports three distinct
synthetic images through the actual browser media port. Each schedule has
fresh IndexedDB, a closed share chooser and no physical capture. The driver
blocks outside requests, local bridge endpoints and WebSockets. Captured
source and model hashes bind the resulting comparison receipts.

Four schedules check the mounted selection and catalog, the installed agent
view host, and the owned browser editor. They compare batch favorite reversal,
selection preservation after a peer removes an unrelated row, Trash, Recover
and confirmed permanent deletion. The viewer follows actual imported IDs,
and the Favorites filter changes only the visible rows. A valid share review
sends the exact reviewed bytes to the closed chooser. A peer mutation changes
the reviewed revision in the real store, and confirming that review refuses
without a second chooser call. Replace original changes the reviewed image
in place while retaining its ID.

IDs are ranked by the actual browser catalog's newest-first order. The positive
window observations compare membership of its first two visible items because
the historical model uses a set with a two-item bound. Browser mutation
revisions are mapped by observed identity changes and saturate at the original
model's revision bound. The stale review schedule changes a revision before
saturation. Navigation through Albums to Recently deleted is an intermediate
step between observed Library and Trash states.

Separate observation-mismatch receipts compare the older window, selection cap,
favorite behavior and patch behavior with current source. Two more receipts
record the full current three-item window exceeding the historical bound and
the Save copy operation producing a distinct ID while preserving the original
bytes and revision. All original profiles and transitions remain unchanged.
The comparison helper selects the existing favorite-change branch of
`StoreEvent` to replay an observed peer change.

The comparison is limited to these browser schedules. It leaves larger and
paged catalogs, concurrent library operations beyond the scheduled peer
changes, Android MediaStore and system permissions, remote agent transport,
external recipients, and temporal fairness as separate obligations.

With authenticated client features and Playwright Chromium prepared, run
`bun test ./test/quint-legacy-photos-library-refinement.test.mjs`.
