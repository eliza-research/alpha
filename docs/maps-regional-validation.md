## Backend evidence

`scripts/maps/prepare-region.py` downloads the dated Geofabrik `monaco-260929.osm.pbf`, Planetiler 0.10.2 and GraphHopper 10.2 into `~/.local/share/alphaphone-maps/monaco`. It builds actual OpenMapTiles vector data; the current output is 23 tiles / 409,600 bytes. The same extract feeds a 2,936-entry named-place/address index and GraphHopper car/foot/bike graphs. Way search locations are representative coordinates, not claimed entrances. No public geocoding, route service, paid credential or device location was used to build the data.

`python3 scripts/maps/test-region.py` passes against the actual local gateway and GraphHopper process. Recorded public-coordinate routes are drive 615.739 m / 62.155 s, walk 307.524 m / 223.650 s, bicycle 341.353 m / 147.332 s, with real nonempty geometry/instructions. Search/detail, no-results, missing-place, exact stored tile bytes, outside-region rejection and unsupported transit are checked. Evidence and source/tool hashes: `test-results/maps-regional-development/backend.json`. These are local backend results, not Android or navigation acceptance.

The loopback gateway binds port 47850, routing 47851, and GraphHopper administration 47852. It suppresses request logging, limits queries/response sizes, uses parameterized search SQL, permits only known local Host values and does not proxy renderer-selected destinations. Queries/coordinates remain on the development machine. Production needs an owned TLS gateway, service operations and an appropriate region deployment; the existing local service is not an internet deployment.

## App behavior

The regional gateway is now a development prototype (#412): only test-mocks builds read `VITE_MAPS_BASE_URL`, and product builds use Eliza Cloud Maps (`apps/app/src/maps/cloud-maps.ts`). For development Android builds only, `http://10.0.2.2:47850` is accepted after reading `DailyApps.surfaceInfo().developmentBuild`, which reports `BuildConfig.ELIZA_DEV_ALLOW_TEST_MOCKS` (a debug variant built with `npm run android:build -- --test-mocks`); distribution debug APKs, like release, reject HTTP and carry no cleartext network configuration. Release Android rejects HTTP even if the environment variable was supplied. Debug Android uses a fixed-endpoint native `AlphaMapsTransport` GET bridge and a custom MapLibre tile protocol, preserving the host WebView’s prohibition on mixed content. Native HTTP checks endpoint paths, forbids redirects, sends no credentials, bounds worker/queue counts and decompressed responses, and disconnects cancelled calls. Gzip MBTiles responses are decompressed natively before returning tile bytes. A browser Vite development server may use `http://127.0.0.1:47850`. No discovery from chat, arbitrary localStorage URLs or public-service fallback occurs.

MapLibre 6.11.2 renders local vector data inside the reference map plane, retaining the surrounding Alpha UI. No third-party style, glyph, sprite, search or route endpoints are used. Attribution remains visible. The initial rendering has geographic land/water/parks/buildings/roads and a selected-place marker; street/place labels use a bundled Public Sans font without remote glyph calls. Viewport gestures are real MapLibre gestures.

Search is limited to regional named objects/addresses. Directions accept a coordinate origin, an explicit native location, or a named origin: other text in the origin field runs the same regional place search plus matching saved places, and choosing a result sets the origin and replans (the route sheet shows "From <name>"). Editing the origin text cancels a pending origin search, so a late response never appears. Real mode changes fetch a fresh route; edited origins clear the previous route immediately. Search results are drawn as tappable map pins, and an explicit Recenter shows the device position marker. Unsupported transit and outside-region endpoints report errors without invented routes or ETAs. Actual routing duration is marked as having no live traffic.

Foreground navigation uses the existing native location plugin, rejects fixes too approximate for guidance, and reports off-route state. The navigation sheet shows the upcoming maneuver's turn arrow, the distance along the route to it, its instruction, the following ("Then") step, and remaining distance, time and arrival (no live traffic); the camera follows the device position and heading. The gateway maps GraphHopper instruction signs to the provider-neutral maneuver vocabulary of patched plugin-maps. It does not move the user with a timer or silently recalculate/send location: rerouting is an explicit "Reroute from here" request (the renderer binding exists; its sheet button awaits the template change listed below). Stop/leave cancels the owned watch. Place detail shows OSM `opening_hours` (verbatim, device time zone not applied), phone (as text; calling stays deferred with Phone) and website when the extract has them. Scheduled transit remains unavailable. Offline tile caching is not represented as offline search/routing; regional-service interruption is an error.

Voice guidance and route/place sharing are implemented. Voice speaks each actual upcoming instruction once through local speech, never auto-sends anything, and is muted, retired or retried explicitly; it is browser-tested against a speech fixture (`test/browser/dev-maps-voice.spec.ts`), not device-qualified on Android local speech. Sharing sends only the explicit selection (place coordinates, or route summary and steps) through the system share sheet, clipboard or an Alpha text dialog; it is browser-tested (`test/browser/dev-maps-share.spec.ts`, `maps-share-layout.spec.ts`), not device-qualified with a native share target.

The renderer takes the provider id and coverage bounds from the configured gateway's `/capabilities` (validated, non-empty bounds) instead of build-time Monaco constants; `regionalDataset` remains only as the descriptor of the development extract. A production HTTPS gateway is still not deployed.

## Reproduction

1. Run `python3 scripts/maps/prepare-region.py` (Java 21, bounded 1 GiB tile JVM, two worker threads).
2. Install PyOsmium 4.1.1 in an isolated Python environment; run `scripts/maps/index-region.py`. The current Mac required a command-scoped `DYLD_LIBRARY_PATH=/opt/homebrew/opt/expat/lib` for its Homebrew Python ABI. Packages were installed into the owned `~/.local/share/alphaphone-maps/python312` directory, not globally.
3. From the data directory run `java -Xmx512m -jar graphhopper.jar server /ABSOLUTE_REPO/scripts/maps/graphhopper.yml`.
4. Stop the router and all dataset writers. Checkpoint/close any SQLite writers, then run `python3 scripts/maps/dataset_manifest.py seal`. This explicitly admits the prepared dataset; it performs no download or reindex.
5. Run `npm run dev:maps -- --port 5194` to verify the dataset and start its router, gateway and app together. In another terminal, run `python3 scripts/maps/test-region.py`.
6. For separate rendered checks start a dedicated `VITE_MAPS_BASE_URL=http://127.0.0.1:47850 npm run dev:ui -- --port 5194 --strictPort`, then run `scripts/maps/test-renderer.mjs` with `ALPHA_BROWSER_MODULES` pointing to the existing Playwright installation.

## Data and software terms

OSM data is ODbL; show OpenStreetMap attribution and preserve source/redistribution obligations. The Planetiler OpenMapTiles profile has its own attribution/license metadata. MapLibre and GraphHopper are independent render/routing tools; importing their UI is unnecessary. The extract date is a freshness statement, not live conditions. Source manifests record tool/data SHA-256 values and URLs. Larger regions, data updates and deployment operations are additional work.

## Connection and permission recovery (source ready)

A failed configured initialization now tells the user to submit a search to retry. The search explicitly retries the existing configured endpoint, shares any pending initialization, and cancels the intended search when the user edits, backs out or leaves. It never polls, discovers a replacement endpoint, or restarts navigation. `scripts/maps/test-recovery-renderer.mjs` passes Chromium connection-failure injection followed by recovery against the actual regional provider, including clearing a previous route on request failure. Evidence: `test-results/maps-regional-development/recovery-renderer.json`. Intercepted browser failures are not native outage proof.

Two additional native methods are gated separately: `deniedLocationAllowsManualOriginAndExplicitPermissionRetry` (`mapsPermission=1`) and `configuredGatewayFailureRecoversOnlyAfterExplicitRetry` (`mapsOutage=1`). Run `scripts/maps/test-native-recovery.mjs permission|outage APP.apk MATCHING_TEST.apk OUTPUT` with an explicit emulator serial. Permission mode uses the actual Android deny/allow-while-in-use buttons, manual-coordinate fallback, and a public Monaco GPS fixture; it restores prior coarse/fine grants and user-set/user-fixed flags. It refuses fixed or one-time permission states. Outage mode additionally requires `ALPHA_MAPS_GATEWAY_PID`; it verifies owner, command, repository working directory and port47850 listener, then briefly pauses/resumes only that process to produce a real native request timeout. GraphHopper and global networking are untouched. Each pause is bounded to25 seconds and SIGCONT is sent on normal/error/interruption cleanup. This tests unresponsiveness, not a physical loss of network connectivity. Both native recovery methods await execution on the next matching APK pair.

## One-command regional browser development

With the regional data already prepared, run `npm run dev:maps` (or `npm run dev:maps -- --port 5194`). This starts the GraphHopper router, loopback gateway and Vite app with the regional endpoint configured. Open the printed `?mode=dev` URL; `npm run dev:maps` sets `ELIZA_DEV_ALLOW_TEST_MOCKS=1`, and that entry point does not exist in production builds. Set `ALPHA_MAPS_JAVA` to a Java executable or `JAVA_HOME` to a compatible runtime if needed; `ALPHA_MAPS_DATA` selects the prepared data directory.

An unexpected child exit stops its siblings and returns failure. The command waits for router and gateway readiness before launching the app, and confirms the app responds before announcing readiness; startup failures clean up already started children.


## Runtime dataset identity — October 3

The capability revision now hashes an explicitly sealed runtime manifest, including the source manifest, OSM extract, actual tiles, place database, GraphHopper JAR, routing configuration and every graph-cache file. Previously, rebuilding the place index or graph could leave the advertised revision unchanged. `dataset_manifest.py verify` recomputes content hashes and refuses drift; startup never silently reseals data.

`dev:maps` verifies before starting its owned router/gateway. The gateway verifies on startup and checks the same file identities before requests and again before sending their captured responses. Changed data returns HTTP503. Both SQLite databases are opened in immutable read-only mode and must be closed and checkpointed: WAL, SHM and journal sidecars are refused during sealing, startup and request checks, because changed rows can otherwise exist outside the main database file. Stop services, review/rebuild, explicitly seal, then restart the router and gateway together for updates. This follows SQLite's [immutable database contract](https://www.sqlite.org/uri.html#uriimmutable), which disables its own locking and change detection; the gateway therefore retains its separate drift checks. The manifest establishes on-disk identity, not a signature or independent proof of what an unrelated pre-existing router loaded.

The synthetic HTTP flow tests revision stability, actual search, changed-index refusal, stale startup, changes after reads, active WAL refusal, explicit resealing and changed/missing graph/tile/router inputs. The separate real-data run uses an isolated clone of the existing Monaco dataset and actual GraphHopper. Evidence is under `test-results/maps-dataset-identity/` in the shared workspace. These checks do not establish public HTTPS operations, current APK acceptance, physical positioning or broader regional coverage.

Final qualification passes all 225 repository checks, TypeScript and the production build (`verify-final.log`), the HTTP identity/WAL regression (`http-flow-immutable.log`), and actual Monaco search/detail/tiles plus drive/walk/bicycle routing (`real-flow-immutable.log`). The real dataset retains revision `65897bf0223d7a5fc1768e51` before startup and after owned-service shutdown. The first repeated real-flow attempt stopped at a port preflight with no listener; the harness now uses the same address-reuse policy as the server and proves it can listen before starting services. ## Navigation guidance and background navigation — October 8

Source: the pinned upstream `plugin-maps` provides step maneuvers, `routeProgress`,
origin search, saved-place matches, rerouting, place opening hours, position heading,
map pins and follow-camera behavior. Its navigation tests run through the existing
Maps verification command. The regional gateway reports provider identity and bounds,
step maneuvers and place details from the sealed dataset.

Background navigation: on Android, Start also starts `AlphaNavigationService`, a `location`-type foreground service with an ongoing notification (next instruction, remaining time and distance, Stop). It never requests location itself; it keeps the existing native location watch, renderer guidance and voice running with the screen off. Its Stop action ends that exact session once and the renderer hears it once (`navigationStopped`); End in the app, leaving Maps, the renderer closing or the task being removed also stop it once. If the platform refuses or ends the service without that Stop, navigation drops back to foreground-only guidance (released when Maps is hidden) instead of ending silently or continuing unseen. A build without the service declaration (and on the web) stays foreground-only. Requires the manifest entries `FOREGROUND_SERVICE_LOCATION` and `<service android:name=".AlphaNavigationService" android:foregroundServiceType="location" android:exported="false"/>`, which are owned by the shell package and not yet in `AndroidManifest.xml`.

Evidence and limits: `scripts/maps/test-renderer.mjs` passes in headless Chromium against the real local regional provider (named origin with a cancelled stale origin search, result pins, maneuver arrow and Then step from the real route, remaining trip, position marker, off-route, arrival, place detail tags), writing `test-results/maps-regional-development/renderer.json`. `test/maps-navigation.test.mjs` covers guidance presentation, the single-stop session contract and the gateway mapping. ## Agent navigation host binding (#412)

`apps/app/src/maps/device-navigation.ts` implements the pinned plugin-maps `MapsDeviceNavigation` contract (`select`, `start`, `reroute`, `stop`) over the existing Maps screen state in `prototype/maps-adapter.ts`. The agent asks; the phone decides:

- Maps opens for an agent request only over Home or Maps itself, on an unlocked, visible launcher screen with no shade, connection panel or assistant window. Otherwise the request is refused and the current screen is kept.
- `select` re-reads an Eliza Cloud place through the phone's own Cloud provider (or drops a pin for a coordinate place) and shows it.
- `start` opens the route sheet for the destination and mode, plans from one fresh device fix and returns `awaiting-confirmation`. Guidance begins only when the user taps Start. Without granted location (no prompt is shown for an agent request), or with a fix older than 30 s, less precise than 50 m or missing after 15 s, it returns `awaiting-location`: the route sheet stays open with the destination, but no route is planned.
- `select` and `start` refuse while a navigation session is active, from Start to End, including while a new route is planned and after arrival.
- `reroute` uses the screen's own "Reroute from here" on the active session and only from a fresh, precise fix. Otherwise, while rerouting or after arrival, it is refused and the current route is kept. `stop` is the screen's End and is idempotent.
- A newer request, Stop, leaving Maps or an account change cancels pending work. A route already being planned may still appear on the sheet, but Start is still required. Refusals carry plugin-maps error codes; upstream actions convert only `MapsError`, so a relay must rebuild one. No device position is returned to the agent. Sharing is unchanged and still needs the user's confirmation.

`apps/app/src/maps/agent-navigation.ts` offers the binding only while Eliza Cloud Maps is installed for the signed-in account (never for the test-mocks regional gateway). Only the launcher renderer offers it, never the ACTION_ASSIST window. Each account gets its own binding; an account or provider change withdraws it before anything else is offered, and the Maps screen already ends guidance on that change. Maps initializes Cloud lazily, so the binding is offered after Maps has connected in this session.

**Resident turn relay.** The reviewed isolated upstream commit `1a5a05db0c80dceeff528d3b70c1724cf84ea153` loads Maps in the mobile resident and provides an authenticated relay ([upstream review](https://github.com/elizaOS/eliza/pull/36303)). Alpha offers its existing phone binding only while sending an authenticated resident conversation turn. The relay binds each command to the owner session, enrolled installation, conversation and unique offer; it rejects revoked credentials, changed owners and stale turns. One-second idle long polls recheck authority after waiting, commands expire after 30 seconds, and uncertain results are never replayed. Turn cancellation reaches the phone's pending location/route work. `relay` in diagnostics indicates an accepted offer, not live provider or device acceptance.

The upstream integration tests exercise the actual Maps action handlers, shared transport, HTTP owner authorization and SQL enrollment store with a scripted phone host. The native gitlinks are unchanged. This establishes the process contract without claiming a physical phone, real GPS or deployed Cloud Maps integration was exercised.

Evidence: `scripts/test-maps-device-navigation.mjs` (through `test/adapter-contracts.test.mjs`) runs the binding against the real shared `MapsController`, a stubbed Cloud provider and a scripted stand-in for the Maps screen (not the adapter itself), covering select, start, reroute, stop, cancellation (including a late GPS result after a turn ends), stale location, account change and unconfigured registration, plus resident loading and relay contracts at the pin. It is not evidence of an agent reaching the phone, a live route, device location or physical navigation.

## Global map display

Alpha restores the existing host-selected OpenFreeMap basemap independently of the Cloud search and routing service. It loads real public imagery and retains attribution and the map privacy disclosure. Opening Maps does not request device location. Coordinates enter the map only through an explicit location request, a selected saved place, or manual entry. Directions are offered only when the configured provider reports a supported mode.

The current upstream pin includes the global renderer. Its bytes match the former carried projection exactly, so client preparation uses that canonical source directly. This source check is separate from Cloud Maps deployment and native or user acceptance.
