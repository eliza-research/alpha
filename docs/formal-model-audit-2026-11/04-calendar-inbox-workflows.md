## Unmodeled state machines (first pass)


- **Device-calendar creation receipts** (`calendar-adapter.ts:64-65,257-268,302-383`): `creationPending`, `creationRecoveryFailed`, two epochs, `separateCreation`, the `calendarSaving` mutex and the `calendarWriteUncertain` latch. Invariant: no second create while a receipt is unacknowledged; the latch must be clearable.
- **Device delete/edit** (`:412-469`): inspect → dispatch → queued / deleted / conflict / unknown.
- **Agent selection** (`:66,388`): key and epoch.
- **Google reader** (`view-adapter.ts:55,121-184`): `epoch`, `attempted`, `loaded`, `reading`, `cachedRead`, `lastReadAt`, `connectOffered`, plus the `pausedOffered` timers.
- **Outbox scheduling** (`outbox.ts:323-385`): single-flight `sending`, wake timer, abort chaining.
- **Linked sync** (`R/calendar-sync-controller.ts:45-243`): review → enable → sync with per-request opt-in. Row states are clean, dirty, conflicted, quarantined, paused. CalendarSync models only consent.
- **Reminders.** `Q/native/DeviceActions.qnt` has one creation and coarse revisions; the following are not covered:
  - creation intents pending → found / retired (`R/reminder-creations.ts:25-76`);
  - operation intents retain → dispatch → receipt → acknowledge (`R/reminder-deletions.ts`, `reminder-adapter.ts:216-256`);
  - tap tokens (`reminder-adapter.ts:29-80`);
  - `reminderRefreshGeneration`, `reminderSaving`, `todoAttempt`.
  - Invariant: every retained intent is eventually resolvable.
- **Clock handoff** (`P/clock-adapter.ts:14,27-93`): `open`, `review`, `busy`, `loading`, two generations, a durable `opening → opened | failed | unknown` record. Invariant: no dispatch after a retired review, and a record exists before dispatch.
- **Browser alarm ringing** (`B/clock.ts:34-50`): `owns`, `ringing`, a Web Lock and a 60 s sound timer.
